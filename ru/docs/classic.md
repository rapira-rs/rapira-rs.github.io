# Режим Classic

Режим Classic выполняет обычный входной PHP-скрипт. Например, php-fpm выполняет файл `public/index.php` для каждого запроса.
Rapira создаёт новый запрос PHP для каждого HTTP-запроса. Она заполняет суперглобальные переменные и выполняет скрипт.
Вывод скрипта становится ответом. Rapira может заменить php-fpm без изменений приложения.

## Чистое состояние на каждый запрос

Каждый запрос получает полный цикл PHP. Он включает инициализацию запроса, выполнение входного скрипта и завершение запроса.
PHP удаляет состояние запроса до начала следующего. К нему относятся глобальные переменные, статические свойства, DI-контейнер и карта объектов ORM.

Объекты и данные запроса не влияют на следующий запрос. Исключения — постоянные соединения и состояние расширений в процессе воркера.
Приложения без поддержки постоянных процессов могут работать в режиме Classic.
Rapira не предоставляет функцию php-fpm `fastcgi_finish_request()`. Используйте `rapira_finish_request()` для отправки ответа до завершения скрипта.
Дополнительная информация находится в разделе [HTTP](/ru/docs/http).

Приложение инициализирует автозагрузчик, конфигурацию, контейнер и маршруты для каждого запроса. См. [Режимы выполнения](/ru/docs/execution-modes).

## Настройка режима Classic

Выберите режим одним из способов:

- `--mode classic` в командной строке, рядом с входным скриптом.
- `mode = "classic"` в секции `[pool]` файла `rapira.toml`.

`--mode` заменяет `pool.mode` из файла конфигурации. Другие параметры командной строки также заменяют соответствующие параметры файла.
Полный список ключей см. в разделе [Конфигурация](/ru/docs/configuration).

Входной скрипт для режима Classic - это обычный PHP:

```php
<?php
// index.php
header('Content-Type: text/plain');
echo "Hello, " . ($_GET['name'] ?? 'anonymous') . "!\n";
echo "Method: {$_SERVER['REQUEST_METHOD']}\n";
```

Выберите режим через CLI или файл конфигурации:

::: code-group

```bash [CLI]
rapira serve --mode classic public/index.php
```

```toml [rapira.toml]
[pool]
entrypoint = "public/index.php"
mode = "classic"
```

:::

Для файла конфигурации выполните `rapira serve --config rapira.toml`.
Относительный `pool.entrypoint` использует каталог файла конфигурации. Относительный путь CLI использует текущий каталог.
Другие параметры см. в разделе [Командная строка](/ru/docs/cli).

## Входной скрипт

Rapira не сопоставляет URL со скриптами PHP. Каждый запрос запускает настроенный входной скрипт.
`$_SERVER['REQUEST_URI']` содержит URL для маршрутизации приложения.
[Middleware статических файлов](/ru/docs/static-files) может возвращать файлы для запросов `GET` и `HEAD`.
Запросы без ответа middleware обрабатывает входной скрипт.

`SCRIPT_FILENAME` всегда содержит путь входного скрипта. `SCRIPT_NAME` содержит имя файла с начальным слешем, например `/index.php`.
`DOCUMENT_ROOT` содержит каталог скрипта. Статические файлы также может отдавать CDN или обратный прокси.
Пример прокси см. в разделе [Запуск в продакшене](/ru/docs/deployment).

## OPcache

Каждый запрос сбрасывает состояние приложения, но не скомпилированный байт-код. Мастер-процесс запускает PHP до создания воркеров.
OPcache создаёт один сегмент общей памяти. Каждый воркер использует одно отображение.
После включения OPcache пул использует кешированные скрипты между запросами. PHP не разбирает входной скрипт повторно.

Режимы Classic и Worker используют один тип пула. Мастер создаёт воркеры, а каждый воркер обрабатывает один запрос одновременно.
Количество воркеров задаёт максимальное число параллельных запросов. См. [Модель процессов](/ru/docs/process-model).

::: info
В режиме Classic `Rapira\handle_request()` бросает `Rapira\Exception\NotInWorkerModeError`. Скрипт завершается вместе с запросом и не может выполнять цикл.
Используйте [режим Worker](/ru/docs/worker) для скриптов воркера.
:::

## Выбор между режимами Classic и Worker

Используйте режим Classic, если приложение не может безопасно сохранять состояние между запросами. Это относится к библиотекам с данными запроса в статических свойствах.
Режим Classic также уменьшает изменения при переходе с php-fpm.
Используйте [режим Worker](/ru/docs/worker), если приложение поддерживает постоянный процесс. Worker удаляет инициализацию приложения из каждого запроса.
Все режимы описаны в разделе [Режимы выполнения](/ru/docs/execution-modes).
