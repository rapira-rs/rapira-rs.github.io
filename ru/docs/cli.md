# Командная строка

Rapira - это один бинарник с единственной подкомандой:

```bash
rapira serve <CONFIG>
```

Команда `serve` запускает PHP, подготавливает плагины и обслуживает запросы на переднем плане. `CONFIG` - это путь к файлу конфигурации, он обязателен. Имя файла может быть любым, а эта документация использует `rapira.toml`.

Запустите `rapira` без аргументов, чтобы показать справку. Запустите `rapira serve --help`, чтобы показать справку по команде. Запустите `rapira --version`, чтобы показать установленную версию.

Файл конфигурации содержит все настройки сервера. Значение в файле переопределяет встроенное значение по умолчанию. `RUST_LOG` и `NO_COLOR` меняют только вывод stderr. Все ключи и форматы адреса `listen` перечислены в разделе [Конфигурация](/ru/docs/configuration).

::: question Можно ли задать режим или адрес listen в командной строке?
Нет. `rapira serve` принимает только файл конфигурации. Задайте `workers`, `mode` и `entrypoint` в `[http.pool]`. Задайте `listen` в `[http]`.
:::

## Относительные пути

Относительный путь в файле конфигурации использует каталог файла конфигурации как базу. Это относится к `http.pool.entrypoint`, `grpc.pool.entrypoint`, относительным путям слушателей `unix:` и ко всем другим ключам с путями. Например, `entrypoint = "public/index.php"` в `/etc/rapira/rapira.toml` разрешается в `/etc/rapira/public/index.php`. Текущий каталог не влияет на эти пути. Список ключей с путями есть в разделе [Относительные пути](/ru/docs/configuration#relative-paths).

## Пример

Этот `rapira.toml` обслуживает HTTP в режиме Dispatcher, режиме по умолчанию:

```toml
[http]
listen = "127.0.0.1:8000"

[http.pool]
entrypoint = "app/dispatcher.php"
```

Чтобы выбрать другой режим, задайте `mode = "worker"` или `mode = "classic"` в `[http.pool]`. См. [Режимы выполнения](/ru/docs/execution-modes).

Запустите сервер с путём к файлу:

```bash
rapira serve rapira.toml
rapira serve /etc/rapira/rapira.toml
```

Сервер слушает `127.0.0.1:8000`. Отправьте запрос этой командой:

```bash
curl http://127.0.0.1:8000/
```

Входные скрипты для режимов Classic и Worker есть в разделе [Быстрый старт](/ru/docs/intro/quickstart). Для входного скрипта режима Dispatcher используйте `dispatcher-sync.php` из каталога [`examples/`](https://github.com/rapira-rs/rapira/tree/main/examples) репозитория. Руководство по программированию есть в разделе [Режим Dispatcher](/ru/docs/dispatcher).

## Остановка сервера

Первый `SIGTERM`, `SIGINT` или `SIGQUIT` запускает контролируемую остановку. Rapira закрывает слушатели, завершает открытые соединения в пределах `[server].stop_timeout_secs`, выключает PHP и завершается. Нажатие `Ctrl-C` в терминале отправляет `SIGINT` и выполняет такую же контролируемую остановку.

Второй `SIGTERM` или `SIGINT` во время завершения соединений вызывает принудительный немедленный выход с кодом `130`. Полная таблица сигналов приведена в разделе [Модель процессов](/ru/docs/process-model).

## Коды завершения {#exit-codes}

| Код | Значение |
| --- | --- |
| `0` | Сервер остановился корректно. `--help`, `--version` и `rapira` без аргументов также завершаются с кодом `0`. |
| `1` | Сбой запуска или работы, например невалидная конфигурация, нечитаемый файл, ошибка привязки адреса, ошибка настройки PHP или `SIGRTMAX` либо сбой слушателя. Ошибка выводится в stderr. |
| `2` | Командная строка не валидна, например неизвестная опция или отсутствует `CONFIG`. |
| `70` | Резидентный воркер достиг `max_boot_failures` до того, как его пул обслужил хотя бы одну единицу работы. |
| `101` | В потоке PHP-воркера произошла паника. |
| `124` | Все воркеры одного пула остались заблокированными дольше 5-секундного дополнительного интервала watchdog после `request_terminate_timeout_secs`. |
| `130` | Второй `SIGTERM` или `SIGINT` пришёл во время остановки и принудительно завершил процесс. |
