# Командная строка

Rapira - это один бинарник с единственной подкомандой:

```bash
rapira serve [OPTIONS] [SCRIPT]
```

Команда `serve` запускает PHP, регистрирует встроенные расширения и принимает запросы. Запустите `rapira` без аргументов, чтобы показать справку. Запустите `rapira serve --help`, чтобы показать доступные параметры. Запустите `rapira --version`, чтобы показать установленную версию.

Файл конфигурации не обязателен. Команда с путём к скрипту может запустить сервер со стандартными настройками.

## Приоритет настроек

Rapira читает настройки в следующем порядке:

**Флаги командной строки > файл конфигурации > встроенные значения по умолчанию.**

Только четыре флага из таблицы и аргумент `SCRIPT` имеют формы командной строки. Остальные настройки используют файл или значение по умолчанию.

Флаг переопределяет соответствующее значение в `rapira.toml`. Значение в `rapira.toml` переопределяет значение по умолчанию. Этот порядок разрешает временное значение для одного запуска. Например, проверьте другой порт без изменения файла.

Неуказанные параметры используют значения по умолчанию из таблицы. Файл управляет масштабированием пула, логированием и ограничениями запросов. Все настройки файла перечислены в разделе [Конфигурация](/ru/docs/configuration).

## Опции

| Опция             | По умолчанию     | Что делает                                                                                       |
| ----------------- | ---------------- | ------------------------------------------------------------------------------------------------ |
| `--config <PATH>` | нет              | Загрузить настройки из `rapira.toml`.                                                            |
| `--listen <ADDR>` | `127.0.0.1:8000` | Адрес прослушивания: `host:port`, `:port` (все интерфейсы) или `unix:<path>`.                    |
| `--processes <N>` | по числу CPU     | Сколько воркеров форкать.                                                                        |
| `--mode <MODE>`   | `dispatcher`     | Режим выполнения: `classic`, `worker` или `dispatcher`. Перекрывает `pool.mode` из файла конфигурации. |
| `SCRIPT`          | обязателен*      | Входной PHP-скрипт. Перекрывает `pool.entrypoint` из файла конфигурации.                         |

\* Обязателен, если в файле конфигурации не задан `pool.entrypoint`. Когда нет ни того, ни другого, `serve` сообщает об ошибке и не запускается.

**`--listen`** принимает три формата адреса. `127.0.0.1:8000` привязывает петлевой интерфейс. Удалённые системы не могут подключиться к этому адресу. `:8080` эквивалентен `0.0.0.0:8080` и привязывает все интерфейсы IPv4. Используйте `[::]:8080` для всех интерфейсов IPv6. `unix:/run/rapira.sock` создаёт Unix-сокет для локального обратного прокси. Заключайте адреса IPv6 в квадратные скобки, например `[::1]:8000`. Rapira не принимает порт без адреса. Используйте `--listen :8080` или `--listen 127.0.0.1:8080`. Rapira не разрешает имена хостов в этом параметре. Используйте `127.0.0.1:8000` вместо `localhost:8000`.

**`--processes`** по умолчанию равен числу логических процессоров. Статическое масштабирование использует его как точное число воркеров. Динамическое масштабирование и `ondemand` используют его как максимальное число воркеров. Дополнительная информация находится в разделе [Модель процессов](/ru/docs/process-model).

**`--mode`** выбирает режим выполнения. Значение по умолчанию — `dispatcher`. В этом режиме скрипт получает каждый запрос от хоста. В режиме `worker` входной скрипт сохраняется и запускает обработчик для каждого запроса. Режим `classic` запускает новый запрос PHP для каждого HTTP-запроса. Флаг переопределяет режим из файла конфигурации. Дополнительная информация находится в разделах [Режим Classic](/ru/docs/classic), [Режим Worker](/ru/docs/worker) и [Режимы выполнения](/ru/docs/execution-modes).

::: info
`pool.scaling` и `pool.mode` - разные ключи. `pool.scaling` задаёт политику, которая определяет размер пула. `pool.processes` задаёт число воркеров, с которым эта политика работает, и его перекрывает `--processes`. `pool.mode` задаёт, что воркер делает с запросом. Флага у `pool.scaling` нет: его задают в файле конфигурации.
:::

## Разрешение пути к входному скрипту

Укажите скрипт аргументом `SCRIPT` или параметром `pool.entrypoint`. Аргумент переопределяет `pool.entrypoint`, но другие параметры файла конфигурации продолжают действовать. Rapira преобразует путь скрипта в абсолютный путь до создания воркеров. Поэтому последующие изменения рабочего каталога не влияют на путь.

Две относительные формы используют разные базовые каталоги:

- Относительный `SCRIPT` из командной строки разрешается относительно **текущего каталога**.
- Относительный `pool.entrypoint` разрешается относительно **каталога файла конфигурации**.

```toml
[pool]
entrypoint = "public/index.php"
```

Эта настройка в `/etc/rapira/rapira.toml` разрешается в `/etc/rapira/public/index.php`. Текущий каталог не влияет на результат.

## Примеры

Типичные запуски:

```bash
rapira serve app/dispatcher.php
rapira serve --mode worker app/worker.php
rapira serve --mode classic public/index.php
rapira serve --listen :8080 --processes 8 app/dispatcher.php
rapira serve --listen unix:/run/rapira.sock app/dispatcher.php
rapira serve --config /etc/rapira/rapira.toml
rapira serve --config /etc/rapira/rapira.toml --listen 127.0.0.1:9000
```

Первая команда не задаёт `--listen`. Поэтому сервер использует адрес по умолчанию. Отправьте запрос этой командой:

```bash
curl http://127.0.0.1:8000/
```

Входные скрипты для команд `--mode classic` и `--mode worker` есть в разделе [Быстрый старт](/ru/docs/intro/quickstart). Входной скрипт для режима Dispatcher возьмите в каталоге [`examples/`](https://github.com/rapira-rs/rapira/tree/main/examples) репозитория: это `dispatcher-sync.php` или `dispatcher-async.php`.

## Остановка сервера

Первый `SIGINT` или `SIGTERM` позволяет завершить текущие запросы. Затем сервер выключает расширения и завершается. Второй сигнал прекращает ожидание и принудительно завершает процесс. Отправляйте сигналы мастер-процессу. Полная таблица сигналов находится в разделе [Модель процессов](/ru/docs/process-model).
