# Режимы выполнения

Rapira запускает PHP в одном из трёх режимов выполнения. Все три режима доступны.

| Режим | Статус | Описание |
| --- | --- | --- |
| [Classic](/ru/docs/classic) | Готово | Входной скрипт выполняется с нуля на каждый запрос, как под php-fpm. |
| [Worker](/ru/docs/worker) | Готово | Резидентный скрипт стартует один раз и обрабатывает запросы в цикле; суперглобальные переменные заново заполняются для каждого запроса. |
| Dispatcher | Готово | Воркер забирает каждый запрос вызовом API и работает с запросом как с обычным значением, а не через суперглобальные переменные. |

Названия режимов - это значения `pool.mode` и варианты перечисления `Rapira\Mode`. Classic удаляет состояние, которое скрипт создал во время запроса. Worker и Dispatcher сохраняют одно запущенное приложение для многих запросов. Доступные режимы определяют состояние приложения и его зависимости от API.

## Classic <Badge type="tip" text="готово" />

Входной скрипт выполняется в новом PHP-запросе, как в php-fpm. Rapira заполняет суперглобальные переменные и выполняет скрипт.
Затем Rapira отправляет ответ и удаляет состояние запроса. Постоянные соединения и состояние расширений остаются в процессе воркера.

Существующее приложение может работать без изменения кода. Rapira встраивает PHP в процесс сервера и не использует FastCGI.

Подробности - в разделе [Режим Classic](/ru/docs/classic).

## Worker <Badge type="tip" text="готово" />

Worker использует те же интерфейсы запросов и ответов, что и Classic. Приложение читает суперглобальные переменные и может использовать `echo`.
Воркер остаётся активным после запроса. Он один раз инициализирует скрипт, а затем запускает цикл.
Для каждого запроса Rapira заполняет суперглобальные переменные и вызывает обработчик. Объекты за пределами цикла остаются доступными.

Приложение инициализируется один раз на воркер, а не на запрос. Это может уменьшить время выполнения запроса.
Статические свойства, синглтоны и глобальное состояние сохраняются для следующего запроса.
Rapira может заменить воркер после заданного количества запросов. Эта замена ограничивает влияние утечки памяти.

Про сам скрипт воркера и его цикл читайте в разделе [Режим Worker](/ru/docs/worker), про ограничение на число запросов до перезапуска - в разделе [Конфигурация](/ru/docs/configuration), а про работу с запросами и ответами - в разделе [HTTP](/ru/docs/http).

## Dispatcher <Badge type="tip" text="готово" />

В режиме Dispatcher скрипт воркера запрашивает каждую единицу работы через API. `Rapira\get_dispatcher()` возвращает диспетчер пула.
`receive(int $timeout = -1)` ожидает следующую единицу. Таймаут задаётся в микросекундах, а `-1` отключает его.
При истечении таймаута функция бросает `Rapira\Exception\TimeoutException`. `tryReceive()` без ожидания возвращает единицу или `null`.
В HTTP-плагине единицей является `Rapira\Http\Exchange`.
Его метод `getRequest()` возвращает `Rapira\Http\Request` с методом, целью, заголовками, телом и адресами.
Методы `writeHead()`, `writeBody()` и `sendFile()` записывают ответ.

Приложение может передавать объект запроса функциям или middleware. Rapira не заполняет суперглобальные переменные в этом режиме.
Приложению с суперглобальными переменными нужен Worker. Другой вариант — адаптер для копирования данных запроса.
Режим выбирает ключ `pool.mode` или флаг `--mode`.

Скрипт управляет количеством активных единиц работы. Последовательный цикл обрабатывает по одной единице.
Он вызывает `receive()`, отвечает на запрос и снова вызывает `receive()`.
Параллельный скрипт запускает [файбер](https://www.php.net/manual/en/language.fibers.php) для каждого запроса. Он вызывает `tryReceive()`, пока файберы активны.
Когда активных файберов нет, цикл ожидает в `receive()`. Такой подход сохраняет несколько активных запросов в одном интерпретаторе.
Параллельность кооперативная. Другой запрос продолжает работу, только когда выполняющийся код приостанавливает свой файбер.
Обрабатывайте по одной единице, если библиотека не поддерживает файберы.

::: info
Dispatcher — значение `pool.mode` по умолчанию. Отдельного руководства пока нет.
Файл [`rapira.stub.php`](https://github.com/rapira-rs/rapira/blob/main/crates/php_sys/rapira.stub.php) описывает интерфейсы `Dispatcher` и `Work`.
Файл [`rapira_http.stub.php`](https://github.com/rapira-rs/rapira/blob/main/crates/php_sys/rapira_http.stub.php) описывает типы HTTP.
Каталог [`examples/`](https://github.com/rapira-rs/rapira/tree/main/examples) содержит `dispatcher-sync.php` и `dispatcher-async.php`.
:::

## Чтение режима во время работы

`Rapira\get_mode()` возвращает режим процесса как вариант `Rapira\Mode`. Варианты: `Classic`, `Worker` и `Dispatcher`.
Вариант соответствует начальному `pool.mode` и не меняется до завершения процесса. Сравнивайте варианты через `===`.
Функция не принимает аргументы и не бросает исключения. Входной скрипт может использовать её для поддержки нескольких режимов.

```php
<?php
// entry.php

use Rapira\Mode;

$app = require __DIR__ . '/bootstrap.php';

match (\Rapira\get_mode()) {
    Mode::Classic => $app->handleOnce(),
    Mode::Worker => $app->runWorkerLoop(),
    Mode::Dispatcher => $app->runDispatcherLoop(),
};
```

::: question Почему режим не меняется, пока процесс работает?
Хост читает `pool.mode` и фиксирует режим до запуска интерпретатора. Каждый запрос воркера возвращает один вариант.
Для изменения режима перезапустите сервер.
:::

## Выбор режима

По умолчанию `pool.mode` равен `dispatcher`. Задайте режим явно в `rapira.toml` или флагом `--mode` в командной строке.

```toml
[pool]
entrypoint = "public/index.php"
mode = "classic"                      # Use "classic", "worker", or "dispatcher". Default: "dispatcher".
```

```sh
rapira serve --mode classic public/index.php
```

Rapira предоставляет все три режима каждому приложению. Код и зависимости приложения могут ограничить выбор.
Используйте Classic, если глобальное состояние не может сохраняться между запросами. Код с суперглобальными переменными требует адаптера для Dispatcher.
Некоторые интеграции фреймворков поддерживают Worker. См. раздел [Фреймворки](/ru/docs/frameworks/).

Режим применяется ко всему экземпляру сервера, а не к отдельным маршрутам. Один экземпляр не может использовать разные режимы.
Запустите несовместимые маршруты в отдельном экземпляре Classic.

Worker и Dispatcher требуют постоянный входной скрипт. Classic не требует его.
Для выбора Classic задайте `mode = "classic"` или передайте `--mode classic`. Затем укажите обычный входной скрипт.
Сервер, бинарный файл и [модель процессов](/ru/docs/process-model) не меняются.
Дополнительная информация находится в разделах [Конфигурация](/ru/docs/configuration) и [Командная строка](/ru/docs/cli).

::: tip
Начните с Classic при замене php-fpm. Проверьте работу приложения.
Выберите Worker после проверки инициализации и состояния между запросами.
:::
