# Laravel

Rapira запускает Laravel в режиме Classic со стандартным скриптом `public/index.php`. Для каждого запроса она запускает новый запрос PHP, как php-fpm.
Изменения приложения не требуются. Режим Worker для Laravel находится в разработке. См. раздел [Режим Worker](#режим-worker).

::: info Проверено на
- **PHP 8.5.8** - NTS, embed SAPI
- **Rapira 0.8.0**
- Базовое приложение **laravel/laravel** с **laravel/framework v13.23.0**

Тесты использовали базовое приложение `laravel/laravel` с двумя дополнительными маршрутами. Rapira запускала приложение в режиме Classic с одним рабочим процессом. Тесты проверяли маршрутизацию, сессии, загрузку файлов, запросы JSON и формы. Они также проверяли кеши конфигурации и маршрутов, ответы с ошибками и 50 последовательных запросов.
:::

## Требования

Установите Rapira по инструкции [Установка](/ru/docs/intro/installation). Также требуется работающее приложение Laravel.
Установите PHP CLI для Composer и `artisan`. Rapira предоставляет PHP как библиотеку, а не как команду `php`.
Composer и `artisan` используют системный PHP CLI. Rapira не использует и не изменяет его.

Проверьте расширения базы данных до первого запуска. Новый проект `laravel/laravel` использует SQLite для базы данных, сессий, кеша и очередей.
Поэтому требуется `pdo_sqlite`. Релизные сборки Rapira включают PDO, `pdo_sqlite` и `sqlite3`.
Полный список расширений см. в разделе [Установка](/ru/docs/intro/installation).
Включите эти расширения при собственной сборке PHP. См. раздел [Сборка из исходников](/ru/docs/intro/build-from-source).
Другой вариант — задать `SESSION_DRIVER=file`, `CACHE_STORE=file` и `QUEUE_CONNECTION=sync`. Эти параметры использовались при тестировании страницы.

## Запуск Rapira

Режим Classic включается явно, поэтому команда прямо его называет:

::: code-group

```bash [CLI]
rapira serve --mode classic public/index.php
```

```toml [rapira.toml]
[pool]
entrypoint = "public/index.php"
mode = "classic"
processes = 4

[http]
listen = "127.0.0.1:8000"
```

:::

Для файла конфигурации выполните `rapira serve --config rapira.toml`.
Относительный `entrypoint` использует каталог файла конфигурации. Все ключи и значения по умолчанию см. в разделе [Конфигурация](/ru/docs/configuration).

Rapira запускает новый запрос PHP для каждого HTTP-запроса. Поэтому жизненный цикл фреймворка совпадает с php-fpm.
Постоянное состояние приложения отсутствует. PHP запускается в мастер-процессе до создания воркеров.
OPcache предоставляет общий кеш скомпилированных скриптов приложения и `vendor/`. См. [Режим Classic](/ru/docs/classic).

Создайте кеши фреймворка перед запуском в продакшене. Обе команды проверены в режиме Classic:

```bash
php artisan config:cache
php artisan route:cache
```

## Маршрутизация и URL

Rapira не сопоставляет URL со скриптами PHP. Каждый запрос запускает входной скрипт.
`$_SERVER['REQUEST_URI']` содержит путь для маршрутизации Laravel. [Middleware статических файлов](/ru/docs/static-files) отвечает на запросы к файлам.
Другие запросы запускают входной скрипт. Проверены маршрутизация, страница 404 Laravel и генерация через `url()`.
Созданные URL являются абсолютными и не содержат `index.php`. Изменять `$_SERVER` или конфигурацию URL не нужно.

Встроенный маршрут `/up` возвращает `200`. Балансировщик или контейнер может использовать его для проверки состояния.
Для статических файлов добавьте `"static"` в `http.middleware`. Задайте для `[http.static].root` каталог `public/`.
Rapira требует оба параметра. Вместо middleware можно использовать CDN или обратный прокси.
Rapira принимает открытый HTTP и оставляет `$_SERVER['HTTPS']` пустым независимо от `X-Forwarded-Proto`.
Если [прокси завершает TLS](/ru/docs/deployment), настройте в Laravel [доверенные прокси](https://laravel.com/docs/requests#configuring-trusted-proxies).
Без этой настройки `url()` создаёт ссылки `http://`.

## Сессии, CSRF и формы

Тесты использовали файловый драйвер сессий. Каждый клиент получил отдельную сессию, а cookie вернулась со следующим запросом.
CSRF не требует настройки Rapira, потому что токен находится в сессии. Режим Classic использует жизненный цикл php-fpm.
Тесты также проверили формы, тела JSON и загрузку файлов. При исключении Laravel вернул обычный ответ `500`.
Следующий запрос не изменился.

## Режим Worker

Режим Worker для Laravel находится в разработке и пока не поддерживается. Запускайте Laravel в режиме Classic.
Дата выпуска поддержки Worker неизвестна.

Жизненный цикл фреймворка требует специальной интеграции. Laravel изменяет привязки, синглтоны и статическое состояние во время запроса.
Это состояние нужно сбросить до следующего запроса. [Octane](https://laravel.com/docs/octane) выполняет сброс для поддерживаемых серверов.
У Rapira пока нет драйвера Octane.

[Symfony](/ru/docs/frameworks/symfony) и [Yii3](/ru/docs/frameworks/yii3) поддерживают постоянные приложения. Для Laravel требуется отдельный процесс сброса состояния.

Собственный воркер Laravel должен полностью реализовать сброс состояния Octane.
Состояние находится в контейнере, синглтонах, запросах, сессиях, аутентификации и статических свойствах.
Неполный сброс может передать старый запрос или сессию следующему пользователю. Не используйте такой воркер без тестов изоляции состояния.
