# Что такое Rapira

Rapira — сервер приложений для PHP, написанный на Rust.

Он встраивает PHP в собственный процесс через embed SAPI — тот самый интерфейс, благодаря которому движок PHP может разместить у себя программа на C. Сервер вызывает интерпретатор напрямую: нет ни протокола FastCGI, ни локального сокета или пайпа, ни сериализации каждого запроса в какой-нибудь протокольный формат и обратно. Пришёл запрос — заполняются суперглобальные переменные и стартует PHP; отработал — байты ответа сразу уходят наружу.

За сам HTTP отвечает фронтенд на базе [Pingora](https://github.com/cloudflare/pingora), прокси-фреймворка Cloudflare на Rust. Он живёт внутри того же бинарника, поэтому второй процесс не нужно ни ставить, ни настраивать, ни поддерживать живым.

## Что понадобится

У Rapira три требования.

- **Только Linux и macOS.** Сборки под Windows нет.
- **PHP 8.4 или 8.5.** В архивы релиза и в пакеты `rapira-php8.4` / `rapira-php8.5` уже вложен подходящий NTS-рантайм PHP embed, так что версия PHP определяется выбранным артефактом и ставить рядом ничего не нужно.
- **Только NTS, никогда ZTS.** Rapira линкуется с непотокобезопасной сборкой PHP. Это важно только при сборке Rapira со своим PHP: потокобезопасную сборку она отвергает сразу, а не ломается потом.

Сборка со своим PHP — другой набор расширений, необычная архитектура, дистрибутив на musl — описана на странице [Сборка из исходников](/ru/docs/build-from-source).

## Два способа запускать приложение

Сегодня Rapira умеет выполнять PHP-приложение двумя способами. Режим воркера включён по умолчанию, классический включается явно: флагом в командной строке или одним ключом в конфиге.

**[Classic](/ru/docs/classic)** выполняет ваш фронт-контроллер с нуля на каждый запрос, ровно как под php-fpm: приложение поднимается, обрабатывает запрос, и всё, что оно успело построить, выбрасывается. Менять в коде ничего не нужно.

**[SAPI Worker](/ru/docs/worker)** держит процесс живым. Резидентный скрипт один раз поднимает приложение — автозагрузчик, контейнер, соединения — и дальше обрабатывает в цикле запрос за запросом, каждый раз заново заполняя суперглобальные переменные. Приложение поднимается один раз при старте, а не на каждом запросе, и состояние живёт дольше запроса.

[Режимы выполнения](/ru/docs/execution-modes) подробнее рассказывают о различиях между ними и о том, как выбрать нужный.
