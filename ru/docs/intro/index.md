# Что такое Rapira

Rapira - сервер приложений PHP, написанный на Rust.

Разработчики RoadRunner проектируют и разрабатывают Rapira. Rapira вызывает PHP напрямую в процессе сервера.

Rapira поддерживает HTTP и [gRPC](../grpc). Каждый протокол имеет собственный слушатель и пул PHP-воркеров.

В [блоге](/ru/blog/) публикуются новости проекта.

## HTTP

Rapira включает HTTP-сервер на основе библиотеки [hyper](https://hyper.rs). Он напрямую принимает открытые HTTP-соединения.
Сервер не завершает TLS. [Прокси завершения TLS](https://en.wikipedia.org/wiki/TLS_termination_proxy) принимает HTTPS от клиента, расшифровывает соединение и передаёт Rapira открытый HTTP.
Настройка прокси описана в разделе [Запуск в продакшене](/ru/docs/deployment).

Rapira поддерживает три режима выполнения PHP:

- Classic: Rapira инициализирует приложение для каждого запроса, как это делает php-fpm.
- Worker: Rapira инициализирует приложение один раз. Цикл обрабатывает запросы, а Rapira заново заполняет суперглобальные переменные PHP для каждого запроса.
- Dispatcher: Rapira инициализирует приложение один раз. Скрипт получает объекты запросов через вызов API. Он может обрабатывать запросы последовательно или одновременно с помощью [файберов](https://www.php.net/manual/en/language.fibers.php).

::: info
На странице [Режимы выполнения](/ru/docs/execution-modes) описано поведение режимов и критерии выбора.
:::

## gRPC

Rapira обслуживает унарные вызовы gRPC, gRPC-Web и Connect на одном слушателе. PHP-приложение получает и возвращает бинарные сообщения protobuf через диспетчер. Мастер загружает схемы сервисов из набора дескрипторов до запуска воркеров.

Пул gRPC использует режим Dispatcher. HTTP и gRPC могут работать вместе с отдельными входными скриптами. Полный пример сервиса, генерация классов protobuf и клиентские команды приведены в разделе [gRPC](../grpc).
