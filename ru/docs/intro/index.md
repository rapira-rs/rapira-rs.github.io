# Что такое Rapira?

Rapira - сервер приложений PHP, написанный на Rust.

Разработчики RoadRunner проектируют и разрабатывают Rapira. Rapira вызывает PHP напрямую в процессе сервера.

Rapira поддерживает HTTP и [gRPC](/ru/docs/grpc). Каждый протокол имеет собственный слушатель и пул PHP-воркеров.

В [блоге](/ru/blog/) публикуются новости проекта.

## HTTP

Rapira включает HTTP-сервер на основе библиотеки [hyper](https://hyper.rs). Он принимает открытые соединения HTTP/1.1 и HTTP/1.0. Rapira не завершает TLS. [Прокси завершения TLS](https://en.wikipedia.org/wiki/TLS_termination_proxy) принимает HTTPS от клиента, расшифровывает соединение и передаёт Rapira открытый HTTP. Настройка прокси описана в разделе [Запуск в продакшене](/ru/docs/deployment).

Rapira поддерживает три режима выполнения PHP:

- Classic: Rapira инициализирует приложение для каждого запроса, как это делает php-fpm.
- Worker: Rapira инициализирует приложение один раз. Цикл обрабатывает запросы, а Rapira заново заполняет суперглобальные переменные PHP для каждого запроса.
- Dispatcher: Rapira инициализирует приложение один раз. Скрипт получает объекты запросов через вызов API. Каждый воркер обрабатывает один запрос за раз.

::: info
На странице [Режимы выполнения](/ru/docs/execution-modes) описано поведение режимов и критерии выбора.
:::

## gRPC

Rapira обслуживает унарные вызовы gRPC, gRPC-Web и Connect на одном слушателе. PHP-приложение получает и возвращает бинарные сообщения protobuf через диспетчер. Мастер загружает схемы сервисов из набора дескрипторов до запуска воркеров.

Пул gRPC использует режим Dispatcher. HTTP и gRPC могут работать вместе с отдельными входными скриптами. Полный пример сервиса, генерация классов protobuf и клиентские команды приведены в разделе [gRPC](/ru/docs/grpc).

## Метрики и проверки работоспособности

Необязательная таблица `[observability]` запускает ещё один процесс, который не выполняет PHP. Подтаблица `[observability.metrics]` включает метрики Prometheus по адресу `/metrics`. Подтаблица `[observability.probes]` включает пробы `/livez` и `/readyz`. Настройка и эндпоинты описаны в разделе [Метрики и проверки работоспособности](/ru/docs/observability).
