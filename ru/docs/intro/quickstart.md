# Быстрый старт

Это руководство запускает приложение в режиме Classic и переводит его в режим Worker. Затем оно сохраняет настройки в файле конфигурации. Для выполнения шагов нужен рабочий бинарник `rapira` с PHP из комплекта. См. раздел [Установка](/ru/docs/intro/installation).

## Режим Classic

Режим Classic доступен любому приложению. Rapira подключает входной скрипт для каждого запроса, как php-fpm. Изменять код не нужно.

Создайте `public/index.php`:

```php
<?php
header('Content-Type: text/plain');
echo "Hello, " . ($_GET['name'] ?? 'anonymous') . "!\n";
echo "Method: {$_SERVER['REQUEST_METHOD']}\n";
```

Создайте `rapira.toml` рядом с каталогом `public`. Ключ `mode` выбирает режим Classic, а `entrypoint` задаёт входной скрипт:

```toml
[http]
listen = "127.0.0.1:8000"

[http.pool]
entrypoint = "public/index.php"
mode = "classic"
```

Запустите сервер с путём к файлу:

```bash
rapira serve rapira.toml
```

Rapira слушает `127.0.0.1:8000`. Отправьте запрос из другого терминала:

```bash
curl '127.0.0.1:8000/?name=world'
```

```
Hello, world!
Method: GET
```

Процессы воркеров остаются активными между запросами. Rapira создаёт воркеры один раз и сохраняет инициализированный интерпретатор PHP в каждом воркере. Режим Classic удаляет состояние скрипта после каждого запроса. Это состояние включает переменные, автозагрузчик и объекты фреймворка.

## Режим Worker

Режим Worker сохраняет скрипт активным. Он инициализируется один раз и ожидает запросы в цикле. Rapira заполняет суперглобальные переменные и вызывает обработчик. PHP может читать `$_GET` и создавать ответ через `echo`. Приложение инициализируется один раз для каждого процесса. См. раздел [Режимы выполнения](/ru/docs/execution-modes).

Создайте `worker.php` в корне проекта:

```php
<?php

// This value remains available for each request in this worker.
$handled = 0;

$handler = static function () use (&$handled): void {
    $handled++;
    header('Content-Type: text/plain');
    echo "Hello, " . ($_GET['name'] ?? 'anonymous') . "!\n";
    echo "worker " . getmypid() . " handled {$handled} request(s)\n";
};

while (\Rapira\handle_request($handler)) {
    gc_collect_cycles();
}
```

`\Rapira\handle_request()` ожидает следующий запрос. Функция вызывает обработчик и возвращает `true`. Во время остановки воркера она возвращает `false`, что завершает цикл. Обработчик читает суперглобальные переменные и отвечает через `echo` и `header()`. Вызывайте `\Rapira\handle_request()` только в цикле верхнего уровня. В других режимах функция бросает `Rapira\Exception\NotInWorkerModeError`.

PHP-модуль Rapira предоставляет `\Rapira\handle_request()`. Поэтому пример не требует автозагрузчика. Приложение с зависимостями Composer должно подключить `vendor/autoload.php` перед циклом.

Остановите сервер Classic с помощью `Ctrl-C`. Оба сервера используют адрес `127.0.0.1:8000`. Измените `rapira.toml` на режим Worker:

```toml
[http]
listen = "127.0.0.1:8000"

[http.pool]
entrypoint = "worker.php"
mode = "worker"
```

```bash
rapira serve rapira.toml
```

```bash
curl '127.0.0.1:8000/?name=world'
```

Выполните команду `curl` несколько раз. Счётчик конкретного воркера увеличивается, когда этот процесс обрабатывает следующий запрос. По умолчанию Rapira создаёт один воркер для каждого логического процессора. Операционная система выбирает воркер для каждого соединения. У каждого воркера есть отдельный счётчик. Идентификатор процесса в ответе показывает выбранный воркер. Задайте `processes = 1` в `[http.pool]` для одного воркера. См. раздел [Модель процессов](/ru/docs/process-model).

Объекты, созданные перед циклом `while`, остаются в памяти до перезапуска скрипта воркера. К ним относятся автозагрузчик Composer, контейнер, соединения, маршруты и шаблоны. Rapira инициализирует это состояние один раз. Только состояние запроса создаётся для каждой итерации.

::: warning
Скрипт воркера должен сбрасывать состояние запроса, которое остаётся в памяти. К этому состоянию относятся статические свойства, глобальные значения и открытые транзакции. См. раздел [Режим Worker](/ru/docs/worker).
:::

Обработчик может использовать `header()`, `http_response_code()` и `echo`. Функция `rapira_finish_request()` отправляет ответ до завершения обработчика. См. раздел [HTTP](/ru/docs/http).

## Файл конфигурации

Файл конфигурации содержит все настройки. Добавьте в тот же файл число воркеров:

```toml
[http]
listen = "127.0.0.1:8000"

[http.pool]
entrypoint = "worker.php"
mode = "worker"
processes = 4
```

```bash
rapira serve rapira.toml
```

::: info
Относительный `http.pool.entrypoint` использует каталог файла конфигурации как базовый. Текущий каталог на него не влияет.
:::

Файл также управляет масштабированием пула, заменой воркеров, тайм-аутами запросов, логированием и pid-файлом. Неизвестный ключ предотвращает запуск. См. [Конфигурацию](/ru/docs/configuration) для всех настроек файла и [Командную строку](/ru/docs/cli) для команды.

## Остановка сервера

Нажмите `Ctrl-C`, чтобы начать контролируемую остановку. Rapira прекращает принимать работу, завершает текущие запросы, останавливает расширения и выходит. Нажмите `Ctrl-C` ещё раз для принудительной остановки. `SIGTERM` работает аналогично. Полная таблица сигналов доступна в разделе [Модель процессов](/ru/docs/process-model).
