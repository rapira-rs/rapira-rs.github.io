# Логирование

Rapira пишет все записи в stderr. К ним относятся события сервера, решения мастер-процесса, события HTTP, диагностика PHP и сообщения приложения.
По умолчанию Rapira записывает предупреждения PHP в этот лог, а не в отдельное место назначения `error_log`. Ко всем записям применяется один фильтр уровней.

Уровень по умолчанию — `error`, поэтому сервер пишет только ошибки. Измените конфигурацию или задайте `RUST_LOG`, чтобы выбрать другой уровень.

## Уровни и формат

Секция `[log]` файла `rapira.toml` управляет логированием:

```toml
[log]
level = "error"   # Use error, warn, info, debug, or trace. Default: error.
format = "plain"  # Use plain or json. Default: plain.
```

`level` задаёт минимальный уровень для всех целей. `error` показывает только ошибки, а каждый следующий уровень добавляет записи.
`trace` показывает все записи. `format` выбирает читаемые строки или один объект JSON на строку.

Оба ключа и вся секция необязательны. Остальные секции файла описаны в разделе [Конфигурация](/ru/docs/configuration).

## Уровни для отдельных целей

`[log.targets]` заменяет глобальный уровень для отдельных целей. Например, он может включить отладку PHP без отладки HTTP:

```toml
[log]
level = "error"

[log.targets]
php = "debug"
http = "warn"
```

Каждый ключ называет одну цель. Остальные цели используют `level`.
Ключ сопоставляется **по префиксу**, поэтому `php` также соответствует `php_sys` и `php_sys::callbacks`. Подмодули перечислять не нужно.

Цели, под которыми пишет сама Rapira:

| Цель     | О чём пишет                                                     |
| -------- | --------------------------------------------------------------- |
| `rapira` | жизненный цикл сервера: старт, жизненный цикл воркеров, остановка |
| `master` | надзор: форки, уборка завершившихся процессов, пересоздание воркеров, перезагрузки, масштабирование пула |
| `http`   | HTTP-фронт: слушающие сокеты, обработка полей запроса и ответа, мягкое завершение |
| `ext`    | чем закончились задачи расширений                                |
| `php`    | вывод и диагностика от самого PHP                                |
| `app`    | записи, которые приложение пишет через `\Rapira\log()`          |

Rapira не пишет отдельную строку доступа для каждого запроса. Записи цели `http` описаны в разделе [Запросы и ответы HTTP](/ru/docs/http).

Зависимость записывает трассировку под путём своего модуля. К этим записям применяется тот же префиксный фильтр.
Каждая запись содержит имя цели. Добавьте его в `[log.targets]`, чтобы уменьшить объём записей.

::: tip
Цель `master` содержит записи о замене воркеров, перезагрузке и масштабировании. Эти события описаны в разделе [Модель процессов](/ru/docs/process-model).
:::

## Диагностика PHP

Rapira направляет диагностику PHP в цель `php`. Тип ошибки определяет уровень записи:

| Тип сообщения                                                                                  | Уровень |
| ---------------------------------------------------------------------------------------------- | ------- |
| Фатальные ошибки - `E_ERROR`, `E_PARSE`, `E_CORE_ERROR`, `E_COMPILE_ERROR`, `E_USER_ERROR`, `E_RECOVERABLE_ERROR` | `error` |
| Предупреждения - `E_WARNING`, `E_CORE_WARNING`, `E_COMPILE_WARNING`, `E_USER_WARNING`           | `warn`  |
| Уведомления - `E_NOTICE`, `E_USER_NOTICE`                                                      | `info`  |
| Сообщения об устаревании - `E_DEPRECATED`, `E_USER_DEPRECATED`                                 | `debug` |

Сообщения об устаревании используют `debug`. Поэтому многочисленные сообщения зависимостей не скрывают предупреждения и ошибки.

Диагностика, исключённая маской [`error_reporting`](https://www.php.net/manual/en/function.error-reporting.php), получает уровень `trace`. Например:

```php
<?php
error_reporting(E_ALL & ~E_DEPRECATED & ~E_USER_DEPRECATED);
```

Эта маска исключает сообщения зависимостей на обычных уровнях. Установите `level = "trace"`, чтобы включить их.
Фатальные ошибки не понижают уровень, потому что они объясняют завершение воркера. Поэтому `error_reporting(0)` не скрывает их.
PHP создаёт `E_CORE_ERROR` и `E_CORE_WARNING` до установки маски. Маска к ним не применяется.

::: info
Rapira отправляет диагностику в лог, а не в ответы. По умолчанию `display_errors` равен `0`, а `log_errors` — `1`.
Значения из `php.ini` заменяют эти значения по умолчанию.
:::

## Логирование из приложения

`\Rapira\log()` пишет запись из PHP в цель `app`. Функция принимает сообщение, необязательный уровень и необязательный массив контекста и доступна во всех режимах выполнения:

```php
<?php

\Rapira\log('order placed');
\Rapira\log('payment declined', \Rapira\LogLevel::Warning);
\Rapira\log('cache miss', \Rapira\LogLevel::Debug, ['key' => 'user:42', 'ttl' => 300]);
```

Уровень - это случай перечисления `\Rapira\LogLevel`, и каждый случай отображается на тот же уровень, которым пользуется остальной лог:

| Случай `LogLevel` | Уровень записи |
| ----------------- | -------------- |
| `Error`         | `error`      |
| `Warning`       | `warn`       |
| `Info`          | `info`       |
| `Debug`         | `debug`      |
| `Trace`         | `trace`      |

`\Rapira\log()` использует `Info`, если параметр `level` не задан. Глобальный фильтр `error` подавляет эту запись, если фильтр не изменить.
`[log.targets]` и `RUST_LOG` одинаково фильтруют записи приложения и сервера.
Например, `app = "debug"` изменяет только цель приложения.

Rapira сериализует массив контекста в JSON и добавляет его как поле `context`. В формате JSON это поле находится в `fields`.
Имена ключей и структура вложенных массивов сохраняются:

```php
<?php

\Rapira\log('checkout failed', \Rapira\LogLevel::Error, [
    'order' => 41,
    'totals' => ['net' => 1250, 'tax' => 250],
]);
```

Rapira раскрывает `Throwable` до сериализации, потому что `json_encode()` возвращает для него пустой объект.
Результат содержит класс, сообщение, код, файл, строку и цепочку `previous`. Он не содержит трассировку стека:

```php
<?php

try {
    $gateway->charge($order);
} catch (\Throwable $e) {
    \Rapira\log('charge failed', \Rapira\LogLevel::Error, ['exception' => $e]);
}
```

`\Rapira\log()` не бросает исключения. Если `jsonSerialize()` бросает исключение, Rapira записывает для этого значения `null`.
Другие ключи сохраняются.

Rapira заменяет значения, которые JSON не может представить. К ним относятся ресурсы, замыкания, `NAN`, `INF` и недопустимые строки UTF-8.
Другие поля сохраняются. Rapira не ограничивает размер контекста.
Передавайте идентификаторы вместо больших объектов.

## Форматы

Rapira пишет оба формата в stderr. Большие записи из разных процессов могут перемешаться, когда эти процессы пишут в один канал stderr.

Rapira не пишет логи в другие места. Перенаправьте stderr для записи в файл.
Менеджер служб может собирать stderr. См. раздел [Запуск в продакшене](/ru/docs/deployment).

**`plain`** предназначен для чтения в терминале: отметка времени, уровень, цель, сообщение:

```text
2026-07-30T09:12:34.567890Z ERROR php: …
```

Rapira использует цвет, когда stderr является терминалом. При записи stderr в файл цвет не используется.
Задайте непустое значение [`NO_COLOR`](https://no-color.org/), чтобы отключить цвет в терминале.

**`json`** предназначен для сборщика логов: по одному объекту на строку:

```text
{"timestamp":…,"level":"ERROR","fields":{"message":…},"target":…}
```

`timestamp` использует RFC 3339, UTC и миллисекунды. Объект `fields` содержит сообщение и другие поля записи.
Rapira экранирует переводы строк. Поэтому каждая запись занимает одну строку.
Вывод JSON не использует цвет.

## `RUST_LOG`

`RUST_LOG` задаёт фильтр логов из окружения. Он позволяет изменить фильтр без изменения конфигурации:

```sh
RUST_LOG=info rapira serve --mode worker worker.php
RUST_LOG=rapira=debug,php=info rapira serve --mode worker worker.php
RUST_LOG=warn,rapira=trace rapira serve --mode worker worker.php
```

Первая команда задаёт `info` для всех целей. Вторая задаёт `debug` для `rapira` и `info` для `php`.
Третья задаёт `warn` для всех целей и `trace` для `rapira`. Цель `rapira` содержит записи инициализации, работы воркеров и остановки.
Для записей мастер-процесса используйте `RUST_LOG=warn,rapira=trace,master=trace`.

::: warning
Непустое значение `RUST_LOG` **заменяет** `level` и `[log.targets]`. Rapira не объединяет фильтры окружения и файла.
Удалите переменную или задайте пустое значение, чтобы использовать файл. `RUST_LOG` не влияет на `format`.
:::
