# Метрики и проверки состояния

Секция `[observability]` запускает слушатель в отдельном потоке (`rapira-obs`) внутри серверного процесса для отдачи проб состояния и метрик Prometheus. Этот поток не выполняет PHP и читает счётчики пулов напрямую из состояния внутри процесса. Архитектура сервера описана в разделе [Модель процессов](/ru/docs/process-model).

Без секции `[observability]` Rapira не запускает этот слушатель. Сборка для Windows не поддерживает эту секцию и отвергает её как неизвестное поле.

## Включение эндпоинтов

Добавьте секцию `[observability]` и хотя бы одну из её подтаблиц. Конфигурация также должна содержать `[http]` или `[grpc]`. Этот минимальный `rapira.toml` включает все эндпоинты:

```toml
[http]
listen = "127.0.0.1:8000"

[http.pool]
entrypoint = "index.php"

[observability]
listen = "127.0.0.1:9180"

[observability.metrics]   # GET /metrics

[observability.probes]    # GET /livez и GET /readyz
```

`[observability.metrics]` и `[observability.probes]` не принимают ключей. Укажите адрес `listen`, который не используют слушатели `http` и `grpc`. Все ключи описаны в разделе [Секция `[observability]`](/ru/docs/configuration#observability).

Запустите сервер, затем отправьте запрос на каждый эндпоинт:

```bash
curl -i http://127.0.0.1:9180/livez
curl -i http://127.0.0.1:9180/readyz
curl http://127.0.0.1:9180/metrics
```

Слушатель пишет записи лога с целью `observability`. Уровни для целей описаны в разделе [Логирование](/ru/docs/logging).

## Эндпоинты

Слушатель обслуживает HTTP/1.1 без TLS. Он отвечает только на эти запросы:

| Запрос | Включает | Статус | Тело |
| --- | --- | --- | --- |
| `GET /livez` | `[observability.probes]` | Всегда `200` | `ok` |
| `GET /readyz` | `[observability.probes]` | `200` или `503` | `ok` или по одной строке `pool <name>: no ready worker` для каждого пула, который не готов |
| `GET /metrics` | `[observability.metrics]` | `200` | Текстовый формат Prometheus |

Любой другой метод или путь получает `404` с пустым телом. Путь выключенной подтаблицы тоже получает `404`. Каждая строка тела заканчивается переводом строки. Пробы используют тип содержимого `text/plain; charset=utf-8`. `/metrics` использует `text/plain; version=0.0.4; charset=utf-8`.

## Живость и готовность

`/livez` не выполняет проверок. Он возвращает `200`, когда сервер отвечает. Во время остановки слушатель observability останавливается вместе с сервером.

`/readyz` проверяет каждый пул PHP: сначала `http`, затем `grpc`. Пул готов, когда хотя бы один его воркер простаивает или занят единицей работы. Воркеры, которые запускаются или завершают работу, не учитываются. `/readyz` возвращает `503` в этих случаях:

- Воркеры пула запускаются и ещё не ожидают единицу работы. В режимах Worker и Dispatcher входной скрипт сначала должен инициализироваться.
- Входной скрипт не может инициализироваться. Воркер повторяет попытку с задержкой, и пул становится готовым после успешной инициализации. Запрос для этого не нужен.
- Все воркеры пула завершают работу.

Перезагрузка оставляет `/readyz` в состоянии `200`, потому что потоки воркеров продолжают работать. Перезагрузка описана в разделе [Сигналы](/ru/docs/process-model#signals).

В некоторых случаях ответа нет совсем. В начале остановки слушатель observability перестаёт принимать соединения. Если воркер достигает `max_boot_failures` до того, как его пул обслужит единицу работы, сервер завершается с кодом `70`. Подробнее см. в разделе [Коды завершения](/ru/docs/cli#exit-codes).

### Пробы Kubernetes

Kubelet отправляет пробы на IP-адрес пода, поэтому петлевой адрес не работает. Привяжите слушатель ко всем интерфейсам пода. Не добавляйте порт в Service.

```toml
[observability]
listen = ":9180"

[observability.probes]
```

```yaml
containers:
  - name: app
    image: registry.example.com/app:latest
    livenessProbe:
      httpGet:
        path: /livez
        port: 9180
      periodSeconds: 10
    readinessProbe:
      httpGet:
        path: /readyz
        port: 9180
      periodSeconds: 5
```

## Метрики Prometheus

Сервер Prometheus на том же хосте может собирать метрики с петлевого адреса. Prometheus использует `/metrics` как `metrics_path` по умолчанию.

```yaml
scrape_configs:
  - job_name: rapira
    static_configs:
      - targets: ["127.0.0.1:9180"]
```

Вывод содержит эти метрики. Метка `pool` имеет значение `http` или `grpc`. Единица работы - это один HTTP-обмен или один вызов gRPC.

| Метрика | Тип | Метки | Значение |
| --- | --- | --- | --- |
| `rapira_workers` | gauge | `pool`, `state` | Воркеры в каждом состоянии. Значения `state`: `starting`, `idle`, `active` и `draining`. |
| `rapira_workers_configured` | gauge | `pool` | Значение `workers` пула. |
| `rapira_requests_total` | counter | `pool` | Единицы работы, которые обработал воркер или отклонил хост. |
| `rapira_requests_failed_total` | counter | `pool` | Единицы работы, которые хост не смог завершить, например потерянный вызов или единица работы, отклонённая после переполнения очереди. |
| `rapira_requests_failed_on_full_queue_total` | counter | `pool` | Единицы работы, которые застали очередь пула полной и не попали в неё. Rapira отклоняет такую единицу, когда очередь остаётся полной 30 секунд. |
| `rapira_requests_queued` | gauge | `pool` | Единицы работы, которые ожидают воркер в пуле. |
| `rapira_script_restarts_total` | counter | `pool` | Перезапуски приложения в потоках воркеров, например после `max_requests`, перезагрузки или фатальной ошибки. |
| `rapira_build_info` | gauge | `version`, `php_version` | Версия Rapira и версия слинкованного PHP. Значение всегда `1`. |

Счётчики запросов описывают работу PHP, а не весь трафик слушателя. Они исключают отказы аутентификации, некорректные JSON-запросы, проверки состояния и рефлексию, которые протокольный слой обрабатывает до передачи в PHP. Хост считает завершённый ответ gRPC `fail()` обработанным без ошибки хоста. Последующая ошибка преобразования ответа в JSON не увеличивает счётчик ошибок. Поэтому `rapira_requests_failed_total` не считает статусы gRPC, отличные от OK.

Счётчики сбрасываются в ноль только при перезапуске сервера. Сбор метрик и пробы читают счётчики внутри процесса и не читают файлы `/proc`.

## Безопасность

Эндпоинты не используют аутентификацию и TLS. `/metrics` показывает версии Rapira и PHP и метрики пулов. Привяжите слушатель к петлевому адресу или к адресу частной сети. Адрес вида `:port` привязывается ко всем интерфейсам IPv4.

Слушатель `unix:` создаёт сокет с правами `0666`. Управляйте доступом через права каталога сокета.

Настройка для продакшена описана в разделе [Запуск в продакшене](/ru/docs/deployment).
