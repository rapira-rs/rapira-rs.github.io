# Статические файлы

Rapira запускает middleware статических файлов до PHP. Middleware отвечает, если путь указывает на файл в корневом каталоге.
Остальные запросы он передаёт следующему обработчику без изменений.

## Включение middleware

Middleware включают две части `rapira.toml`. Добавьте `static` в список `[http].middleware`.
Затем добавьте секцию `[http.static]` с каталогом файлов.

```toml
[http]
middleware = ["static"]

[http.static]
root = "public"     # Required. Relative paths use this file's directory.
forbid = [".php"]   # Optional. This list replaces the default.
```

`middleware` задаёт цепочку middleware в том порядке, в каком они перечислены. Сейчас `static` - единственное имя, которое он принимает.

`root` задаёт каталог с файлами. Значения по умолчанию нет.
Относительный путь использует каталог файла конфигурации. Это же правило действует для `pool.entrypoint`.

`forbid` содержит расширения, которые middleware не отдаёт. Значение по умолчанию — `[".php"]`.
Явный список заменяет значение по умолчанию. Например, `forbid = [".php", ".env"]` блокирует оба расширения.
Значение `forbid = []` разрешает все файлы, включая исходный код PHP.
Каждая запись начинается с точки, содержит минимум два символа и не содержит `/` или пробелы.
Недопустимая запись останавливает запуск сервера.

Остальные ключи файла собраны на странице [Конфигурация](/ru/docs/configuration).

::: question Почему элемент `forbid` обязан выглядеть как расширение?
Middleware сравнивает запись с концом имени файла. Разделитель или пробел не может завершать имя файла.
Поэтому такая запись не может защитить файл. Проверка отклоняет её.
:::

## Проверки при запуске

Сервер проверяет корневой каталог до приёма запросов. Путь должен существовать, быть каталогом и разрешать поиск серверному пользователю.
Ошибка проверки останавливает запуск и указывает путь.

Обе части конфигурации должны присутствовать вместе. Запись `"static"` требует секцию `[http.static]`, а секция требует запись.
Rapira также отклоняет повторяющиеся имена middleware.

::: question Почему сервер проверяет корневой каталог дважды?
Первая проверка читает метаданные и подтверждает тип каталога. Вторая разрешает `.` и проверяет право поиска.
Права поиска и чтения используют разные биты. Поэтому первая проверка может пройти, а вторая — завершиться ошибкой.
Требования описаны в документации [`stat`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/stat.html).
:::

## Правила отдачи

Middleware берётся за запрос только тогда, когда метод - `GET` или `HEAD`. Любой другой метод уходит в PHP.

Дальше всё решает путь:

- Путь, в котором сегмент начинается с `.`, уходит в PHP, поэтому `/.env`, `/.git/config` и `/../outside.txt` до файловой системы не доходят.
- Проверка `forbid` идёт по пути с раскрытыми процентными последовательностями и сравнивает последний сегмент без учёта регистра, поэтому при `.php` в `forbid` в PHP уходят и `/index.php`, и `/index%2Ephp`, и `/Upper.PHP`.
- URL каталога уходит в PHP. Индексный файл middleware для него не отдаёт - ни с завершающей косой чертой, ни без неё.
- Путь, за которым нет файла, уходит в PHP. Ошибка прав доступа тоже уходит в PHP, как и имя, которое файловая система не принимает.
- Любая другая ошибка чтения даёт ответ `500`. Такой запрос до PHP не доходит, а сама ошибка пишется в лог в цель `http`.

PHP получает переданный запрос без изменений. См. раздел [Запросы и ответы HTTP](/ru/docs/http).

::: question Почему на URL каталога не приходит `index.html`?
PHP управляет пространством URL, поэтому URL каталога является маршрутом приложения. Автоматический индекс создал бы два возможных ответа.
Он также не дал бы входному скрипту обработать `/`.
:::

::: question Как middleware отличает промах от ошибки чтения?
Шесть результатов означают отсутствие доступного файла. Путь может отсутствовать, быть недоступным или указывать на каталог.
Компонент пути может иметь неправильный тип. Имя может быть слишком длинным или содержать нулевой байт.
В этих случаях запрос передаётся PHP. При других ошибках чтения middleware возвращает `500`.
:::

## Поля ответа

Перечисленные ниже поля относятся к ответу, который отдаёт файл. В ответе `500`, который формирует сам middleware, их нет.

`Content-Type` middleware выставляет по расширению файла. Имя с неизвестным расширением получает `application/octet-stream`.

Ответ содержит `ETag` и `Last-Modified`. Middleware создаёт `Last-Modified` из времени изменения файла.
Он создаёт `ETag` из времени изменения и длины. Файл без времени изменения не получает эти поля.
Время до начала эпохи отключает только `ETag`.

Middleware отвечает `304 Not Modified`, когда поле `If-None-Match` совпадает с `ETag`. Запрос без поля `If-None-Match` получает `304 Not Modified`, если время изменения файла не позже времени в поле `If-Modified-Since`. В таком ответе есть только `ETag` и `Last-Modified`, а тела нет.

В ответе есть и `Accept-Ranges: bytes`. Запрос с полем `Range` получает `206 Partial Content` вместе с полем `Content-Range`. Диапазон, которого файл не покрывает, получает `416 Range Not Satisfiable`, и такой запрос до PHP тоже не доходит.

## Кеш файлов

Каждый воркер хранит отданные файлы в памяти. Настроить кеш нельзя.

Запись кеша действует одну секунду. Затем следующий запрос использует `stat` для сравнения файла.
Воркер сохраняет запись с теми же временем изменения и длиной. Изменённый файл он читает повторно.

Файл больше 256 КиБ в кеш не попадает никогда. Такой файл на каждом запросе читается с диска.

Один воркер хранит не больше 16 МиБ. Полный кеш продолжает отдавать текущие записи.
Перед отклонением нового файла он удаляет устаревшие записи. Каждый воркер использует до 16 МиБ для кеша.
Перезапуск очищает кеш.

Каждый воркер проверяет свои записи. Удалённый файл влияет на ответы не позже чем через одну секунду.
Изменённый файл влияет на ответы, если меняется время изменения или длина.
Изменение прав не удаляет запись, если время и длина не меняются.
Удалите файл или перезапустите сервер для удаления записи. При замене измените время или длину файла.

Корневой каталог должен находиться на локальном хранилище. Middleware выполняет `stat` и `open` в потоке обработки запросов.
Медленная файловая система задерживает другие соединения воркера.

::: question Как кеш замечает, что файл изменился?
Кеш сравнивает время изменения и длину с сохранёнными значениями. ETag содержит те же значения.
Кеш не обнаруживает замену, которая сохраняет оба значения. Поэтому измените время или длину каждого заменённого файла.
:::
