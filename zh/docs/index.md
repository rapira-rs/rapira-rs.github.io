# 什么是 Rapira

Rapira 是用 Rust 编写的 PHP 应用服务器，它顶替的正是平时 php-fpm 所在的位置：监听 socket 归它掌管，对外由它讲 HTTP，你的 PHP 代码也由它来跑。

它的与众不同之处，在于服务器和解释器之间夹着什么——答案是什么都没有。Rapira 通过 PHP 的 embed SAPI 把解释器嵌进自己的进程，这正是让 C 程序托管 PHP 引擎的那个接口。宿主直接调用解释器：没有 FastCGI 协议，没有本地 socket 或管道，也不必在每个请求上把数据序列化成某种传输格式再还原回来。请求一到，超全局变量填好，PHP 就开始执行；执行完毕，响应字节直接发出去。

HTTP 本身由一个基于 [Pingora](https://github.com/cloudflare/pingora) 构建的接入层处理——Cloudflare 的边缘网络就跑在这个 Rust 代理框架上。它已经打包进二进制文件，所以不用再安装、配置和守护第二个进程：一棵 `rapira` 进程树就是完整的服务器。

## 运行前提

在往下走之前，有几条限制值得先知道，因为它们没有商量的余地：

- **只支持 Linux 和 macOS。** 没有 Windows 版本。
- **PHP 8.4 或 8.5。** 发行压缩包以及 `rapira-php8.4` / `rapira-php8.5` 软件包里都自带了对应版本的 NTS PHP embed 运行时，你选哪个产物，跑的就是哪个版本，不需要另外再装一份 PHP。
- **只用 NTS，绝不用 ZTS。** Rapira 链接的是非线程安全的 PHP。只有当你拿自己的 PHP 来编译 Rapira 时，这件事才需要你操心——线程安全的构建会在那一步直接被拒绝，而不是拖到后面才出问题。

想换成自己的 PHP 来构建？比如换一套扩展、跑在特殊架构上，或者用基于 musl 的发行版——参见[从源码构建](/zh/docs/build-from-source)。

## 运行应用的两种方式

今天的 Rapira 提供两种执行 PHP 应用的方式。默认拿到的是 worker；经典模式需要主动开启——命令行加个参数，或者配置文件里改一个键。

**[经典模式](/zh/docs/classic)**是大家熟悉的那一种。每个请求都会把你的前端控制器从头执行一遍，和在 php-fpm 下一模一样：应用启动、处理请求，然后把构建出来的一切统统丢掉。代码一行都不用改，所以对已有应用来说，它是最实在的起点；一旦技术栈里有什么东西撑不过第二个请求，它也是你的退路。

**[SAPI Worker](/zh/docs/worker)** 则让进程一直活着。一个常驻脚本只启动一次应用——自动加载器、容器、各种连接——之后就进入循环，每次填好超全局变量，一个接一个地处理请求。启动开销只在进程起来时付一次，不再摊到每个请求上；但状态从此比请求活得更久，这对你思考代码的方式是个实打实的改变。

这两种只是一条更长阶梯上的头两级——`Classic → SAPI Worker → PSR Worker → Async`——每往上一级，PHP 对请求生命周期的掌控就多一分。目前只发布了前两级；[执行模式](/zh/docs/execution-modes)会讲清整条阶梯，以及怎么判断你的应用实际能爬到哪一级。

::: tip
应用能爬到哪一级，取决于应用自身，而不是 Rapira 设下的限制。撑不过第二个请求的全局状态会把你按在 Classic 这一级——这是你的代码在说话，而且它是可以改的。
:::

::: question 用 Rapira 需要重写我的应用吗？
不需要。经典模式下，普通的前端控制器原封不动就能跑——Rapira 直接顶替 php-fpm 的位置，你的代码根本察觉不到区别。要不要转向 worker 是另一件事，完全可选，什么时候想动手都行。
:::
