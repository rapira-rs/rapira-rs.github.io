# 静态文件

Rapira 用静态文件中间件提供某个目录里的文件，时机在请求到达 PHP 之前。这个中间件待在 HTTP 接入层里、PHP 处理器的前面：请求能在它的根目录下解析出一个文件，它就自己作答；其余请求原封不动往中间件链的下游传。

## 启用中间件

`rapira.toml` 里有两处配置负责打开这个中间件：`[http]` 的中间件列表里写上 `static` 这个名字，再加一个 `[http.static]` 小节说明文件在哪里。

```toml
[http]
middleware = ["static"]

[http.static]
root = "public"     # required; a relative path resolves against this file's directory
forbid = [".php"]   # optional; an explicit list replaces this default
```

`middleware` 按列表顺序放着整条中间件链，目前它只接受 `static` 这一个名字。

`root` 指明中间件从哪个目录提供文件。它没有默认值，所以这一节必须写它。相对路径按配置文件所在的目录解析，和 `pool.entrypoint` 一样。

`forbid` 放着中间件永不提供的扩展名。它的默认值是 `[".php"]`，而显式写出的列表会整个替换这个默认值：`forbid = [".php", ".env"]` 把这两种扩展名都挡在应答之外，`forbid = []` 则把根目录下的每个文件都提供出去，PHP 源码也不例外。每一项都是一个带前导点的扩展名，至少两个字符，不含 `/`，也不含空白字符。不符合这个形状的条目会挡下启动。

这个文件里的其余键在[配置](/zh/docs/configuration)那一页。

::: question 为什么 `forbid` 里的条目必须长得像扩展名？
中间件是把每一项当作文件名的后缀来匹配的。分隔符或空格永远不可能落在文件名的末尾，所以带着它们的条目什么都匹配不到，本想保护的那个文件依旧可达。与其接受一道形同虚设的防线，这里直接拒绝这样的条目。
:::

## 启动校验

服务器在提供任何东西之前先检查根目录：它必须存在、必须是目录，而且服务器所用的那个用户必须能搜索它。任何一项不过关，启动就会中止，并报出这个路径。

配置里的这两处必须彼此对得上。写了 `middleware = ["static"]` 却没有 `[http.static]` 小节会挡下启动，有 `[http.static]` 小节却没写进 `middleware` 同样挡下启动。`middleware` 里重复出现的名字也会被拒绝。

::: question 为什么服务器要对根目录测两次？
第一次读根目录的元数据，说明这个路径存在，而且它是一个目录。第二次在根目录里解析 `.`，说明它具备搜索权限，而根目录下的每一次读取都需要这个权限。目录的搜索权限和读取权限是两个不同的位，所以过了第一次测试的根目录，仍然可能过不了第二次。每个调用各需要哪些权限，见 [`stat`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/stat.html)。
:::

## 提供文件的规则

只有方法是 `GET` 或 `HEAD` 时，中间件才会接手这个请求，其余方法一律交给 PHP。

剩下的由路径决定：

- 某一段以 `.` 开头的路径交给 PHP，所以 `/.env`、`/.git/config` 和 `/../outside.txt` 永远碰不到文件系统。
- `forbid` 检查跑在百分号解码之后的路径上，比较最后一段时不分大小写，所以只要 `forbid` 里有 `.php`，`/index.php`、`/index%2Ephp` 和 `/Upper.PHP` 就全都交给 PHP。
- 目录形式的 URL 交给 PHP。中间件不为它提供索引文件，带不带末尾斜杠都一样。
- 背后没有文件的路径交给 PHP。权限错误同样交给 PHP，文件系统不接受的名字也一样。
- 其余的读取失败以 `500` 作答。这类请求不会到达 PHP，失败记在 `http` 这个 target 上。

交给 PHP 的请求，其请求体、字段和扩展数据都原封不动。PHP 从中读到什么，见 [HTTP 请求与响应](/zh/docs/http)。

::: question 为什么目录形式的 URL 不用 `index.html` 作答？
URL 空间归 PHP 管：目录形式的 URL 就是应用的一条路由。隐式的索引文件会让同一个 URL 有两个答案，一个来自文件系统，一个来自路由器，还会把 `/` 从前端控制器手里夺走。
:::

::: question 中间件怎么区分“没有这个文件”和“读取失败”？
有六种结果意味着没有文件可提供：路径不存在、进程无权读取、路径是一个目录、路径中的某一段不是目录、名字对文件系统来说太长，以及名字里含有 NUL 字节。每一种都算未命中，请求继续走向 PHP。其余的错误说明文件存在却读不出来，这种情况 PHP 同样答不了，所以中间件以 `500` 报出去。
:::

## 响应字段

下面这些字段属于真的提供了一个文件的那种应答。中间件的 `500` 应答一个都不带。

中间件按文件扩展名设置 `Content-Type`。扩展名认不出来的文件得到 `application/octet-stream`。

应答带有 `ETag` 和 `Last-Modified` 两个字段，中间件用文件的修改时间构造它们。没有修改时间的文件这两个字段都拿不到，修改时间早于纪元的文件拿不到 `ETag`。

请求的 `If-None-Match` 或 `If-Modified-Since` 字段和文件对得上时，中间件以 `304 Not Modified` 作答。这条应答只带 `ETag` 和 `Last-Modified` 字段，没有响应体。

应答还带着 `Accept-Ranges: bytes`。`Range` 请求以 `206 Partial Content` 加一个 `Content-Range` 字段作答。文件满足不了的范围以 `416 Range Not Satisfiable` 作答，这类请求同样不会到达 PHP。

## 文件缓存

每个 worker 进程都把提供过的文件留在内存里。这份缓存没有任何配置键，下面这些数值都是固定的。

一条缓存记录的新鲜期是一秒。过了这个窗口的第一个请求会跑一次 `stat`，修改时间和长度仍然和文件对得上就刷新这条记录，文件变了就重新读一遍。

大于 256 KiB 的文件从不入缓存，这种文件每个请求都从磁盘流式读出。

一个 worker 最多存 16 MiB。到了这个上限，缓存照旧提供手上已有的记录，并在拒绝新文件之前先丢掉过期的记录。因此内存开销是 `pool.processes` 里每个进程各自最多 16 MiB。重启会把缓存清空。

每个 worker 各自校验自己的记录，所以根目录下的改动最迟一秒之后就能被客户端看到。删掉的文件和被替换的文件都会在这个窗口内离开缓存。单单改权限并不会让记录失效，因为 `stat` 报出来的修改时间和长度和之前一模一样：要把它从缓存里踢出去，就删掉这个文件、替换它，或者重启服务器。

根目录必须放在本地存储上。中间件是在负责处理请求的那个运行时线程上跑 `stat` 和 `open` 的，所以文件系统要是慢慢吞吞才应答这两个调用，这个 worker 上其余的连接都会被拖住。

::: question 缓存怎么发现文件变了？
它拿文件的修改时间和长度，跟自己存下来的那两个值比对，ETag 编的也是这一对值。修改时间和长度都没变的替换发现不了，所以靠拷贝文件来发布的部署流程，必须让每个被替换的文件带上新的修改时间或新的长度。
:::

更多内容见[配置](/zh/docs/configuration)。
